# GitHub to Render deployment

The repository is configured for this flow:

1. Push to `main`.
2. GitHub Actions builds both Docker images.
3. After both builds succeed, the workflow calls the two Render deploy hooks.
4. Render builds the committed Dockerfiles and deploys the API and frontend.

## One-time Render setup

1. Create a Render account and create a Blueprint from this repository using `render.yaml`.
2. Provide a hosted PostgreSQL connection string. Render's free web services do not provide a permanently free PostgreSQL database, so use a free external PostgreSQL provider such as Neon or Supabase.
3. Set these API environment variables in Render:
   - `DATABASE_URL`: SQLAlchemy PostgreSQL URL, usually `postgresql+psycopg://...`
   - `POSTGRES_URL`: async LangGraph URL, usually `postgresql://...`
   - `HF_Token`: Hugging Face token
4. Create a deploy hook for each Render service.
5. Add these GitHub repository secrets:
   - `RENDER_API_DEPLOY_HOOK_URL`
   - `RENDER_WEB_DEPLOY_HOOK_URL`

`JWT_SECRET` is generated by the Blueprint. The frontend receives the API's internal Render hostname through `BACKEND_HOST`; Nginx proxies `/api/*` to port `8000`.

## Local Docker checks

```powershell
docker build -t mlfastapi-backend ./backend
docker build -t mlfastapi-frontend ./frontend
```

The frontend container expects `BACKEND_HOST` at runtime. Render supplies it from the API service automatically.
